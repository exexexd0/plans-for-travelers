# Архитектура

Целевая структура чистового `plans-for-travelers`. Сейчас здесь реализован
фронтенд с демо-маршрутами и каркас бэкенда с общими типами и контрактами.
Поиск, сценарии, HTTP API и внешние клиенты ещё не реализованы.
Предлагаемый стек бэкенда — Python + FastAPI.

## Чистая архитектура

Зависимости направлены внутрь:

```text
API ────────────────→ application → domain
infrastructure ────→ application → domain
```

- `domain` содержит общие типы и правила, без FastAPI, HTTP, LLM и файлов.
- `application` описывает сценарии через контракты из `ports.py`.
  Сборщик поездки не импортирует конкретный BM25 или клиент модели.
- `infrastructure` реализует эти контракты: поиск, загрузку данных, LLM и OSRM.
- `api` проверяет HTTP-вход, вызывает сценарий и преобразует результат в JSON.
  Поиск и сборка маршрута внутри обработчиков не реализуются.
- `main.py` создаёт реализации, загружает корпус, строит индекс и передаёт
  зависимости сценариям. Одна и та же сборка компонентов используется при проверке.

Фронтенд получает результат только через API. Benchmark вызывает сценарии
приложения, поэтому для проверки поиска не требуется запускать браузер.

## Путь запроса

1. Пользователь выбирает Иваново, интересы, дату начала и 1–7 дней.
2. `buildRoute` вызывает HTTP-клиент; `App.tsx` сохраняет результат или ошибку.
3. API проверяет вход и передаёт его в `build_trip`.
4. Сценарий строит запрос из интересов и вызывает BM25 через контракт поиска.
5. LLM получает найденные документы с ID и настройки поездки.
6. Сценарий проверяет ID и разбиение на запрошенное число дней.
   Маршрутизация работает отдельно для каждого дня.
7. API возвращает поездку с датами, описанием и списком дней.
8. Интерфейс показывает поездку, выбранный день, его места и карту.

Разбиение по дням относится к `build_trip`, а не к BM25.
Экран генерации ждёт результат вместо таймера. Дизайн сохраняется.

## Контракты для параллельной работы

| Контракт | Назначение |
|---|---|
| Документ | ID, название, город, текст для поиска, координаты, источник; отсутствие необязательных данных явно обозначается |
| Поиск | Запрос, город, лимит, фильтры и исключённые ID → найденные документы с баллами BM25 |
| LLM | Найденные документы и настройки → структурированный результат с ID источников |
| Маршрутизация | Упорядоченные места одного дня → геометрия и доступные расчёты пути |
| API поездки | Город, интересы, days, start → описание поездки и массив дней с местами |

Даты в JSON — строки `YYYY-MM-DD`; время суток и часовые пояса для них не нужны.
Фронтенд преобразует даты в свои типы в `api.ts`. Сейчас `Stop` содержит только
`name` и `photo`, а `RouteDay.date` — объект `Date`: эти типы нужно согласовать
с ID, координатами и ответом сервера до подключения.

## Контракты каркаса

Импорты выполняются из корня проекта: `app.backend...`.
`domain/models.py` содержит dataclass-модели без внешних зависимостей.
`application/ports.py` содержит Protocol-контракты; реализации передаются сценариям извне.

- `Place`: `id`, `name`, `city`, `text`, необязательные `lat`, `lon`, `source`,
  `category`. В категории используется значение из корпуса, без придуманного списка.
- `SearchHit`: `place`, `score`.
- `SearchPort.search(query, *, city, limit, categories=(), excluded_ids=())`:
  синхронный вызов, возвращающий последовательность `SearchHit` по убыванию балла.
  `city=None` означает поиск по всему корпусу; пустые фильтры не ограничивают выдачу.
- `TripRequest`: `city`, `interests`, `days`, `start` (`datetime.date`).
- `Trip`: `city`, `description`, `days`; каждый `RouteDay` содержит дату, заголовок,
  описание, места и необязательный результат маршрутизации `DayRoute`.
- `Answer`: `text`, `source_ids`, `rejected` — результат ответа на вопрос benchmark.

Клиенты LLM и маршрутизации — асинхронные контракты. Внутренние модели не являются
утверждённым JSON-контрактом: его преобразование и проверка остаются задачей API.
В каркасе нет готовых реализаций; незавершённые точки входа явно завершаются ошибкой,
а не возвращают демонстрационный успешный результат.

Пайплайн `app/pipeline/rag` читает `.env` и относительный `SOURCE_PATH` из
корня проекта; результаты сохраняются в `app/pipeline/artifacts/`.

Из корня проекта генерация также запускается командой `python -m rag route`.
