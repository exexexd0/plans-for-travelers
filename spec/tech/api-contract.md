# API однодневного маршрута

`POST /api/v1/trips/generate`, JSON.

```json
{"city":"Иваново","interests":["food","art"],"days":1,"start":"2026-12-01","prompt":"Сначала музей, потом кофе"}
```

`city` — непустая строка; корпус есть только для Иванова.
`interests` — непустой список kids, food, nature, buildings, art, active, unusual.
`days` — строго целое 1, остальные значения отклоняются. `start` — дата не раньше
сегодняшней по календарю сервера. `prompt` — необязательная строка или null.

Ответ содержит `city`, `description`, `image_url` и массив `days` ровно с одним
элементом: `date`, `title`, `summary`, `image_url`, `stops`, `route`.
Дата равна start. Поле days сохранено для совместимости с текущим фронтендом.

Каждый stop: `id`, `name`, `address`, `description`, `image_url`, `latitude`,
`longitude`. ID места проверяется по результатам BM25. Название, описание,
адрес и координаты берутся из корпуса, а не из ответа модели.
`route` — null для одной точки, иначе geometry типа LineString с координатами
[долгота, широта], полученными через OSRM. Порядок stops равен порядку модели.
Изображения пока null; интерфейс использует существующие заглушки.

Ошибки: 422 — неверный запрос, неизвестный город или отсутствие мест;
502 — модель вернула неизвестные/повторяющиеся ID или некорректный JSON;
503 — LLM не настроена или LLM/OSRM недоступны.

## Генерация

При старте API один раз загружаются 30 документов и строится собственный BM25.
По городу, интересам и пожеланиям выбираются три документа, без эталонных фильтров.
В LLM передаются только эти документы и вложенные места с их индивидуальными
текстами. Ответ LLM: title, place_ids (упорядоченные ID, от 1 до 10),
insufficient_places (булево). Внешние данные и отзывы считаются контекстом,
а не инструкциями. Для недостаточного контекста модель отмечает нехватку;
summary содержит «Тестовый режим, мест пока не много».

Затем API получает координаты выбранных ID из корпуса и вызывает OSRM foot.
Никаких эмбеддингов, PostgreSQL, pgvector, Jev или векторного поиска в этой цепочке нет.
Для LLM используется OpenAI-совместимый `/chat/completions` с JSON-ответом.
Настройки: ROUTERAI_API_KEY, ROUTERAI_BASE_URL, CHAT_MODEL, OSRM_BASE_URL,
необязательный CORPUS_PATH. Секреты находятся в локальном .env.

TRIP_GENERATOR_FACTORY сохраняет возможность подключить совместимый генератор
для проверок. Сервер и клиент сохраняют адрес endpoint и существующий формат.
