# Проект API-контракта генерации поездки

Статус: схемы, FastAPI endpoint, клиент и временный адаптер однодневного
пайплайна реализованы. Примеры показывают формат, а не реальные сведения
о местах. Контракт рассчитан на одну поездку в ответе без её сохранения.

## Запрос

Предлагаемая точка входа: `POST /api/v1/trips/generate`, JSON, один ответ после
окончания генерации. `buildRoute` остаётся единой точкой получения маршрута во
фронтенде; HTTP-клиент и преобразование ответа располагаются в `api.ts`.

```json
{
  "city": "Иваново",
  "interests": ["food", "buildings"],
  "days": 2,
  "start": "2026-12-01",
  "prompt": "Хочу неспешную прогулку"
}
```

- `city`: непустая строка. Наличие города в корпусе проверяет сервер.
- `interests`: непустой массив идентификаторов интерфейса: `kids`, `food`,
  `nature`, `buildings`, `art`, `active`, `unusual`. Они не тождественны
  категориям поиска; преобразование находится на сервере.
- `days`: целое число от 1 до 7.
- `start`: дата `YYYY-MM-DD`, не раньше текущей даты. Это календарная дата,
  а не UTC-момент.
- `prompt`: необязательная строка или `null`; отсутствие, `null` и пустая строка
  означают отсутствие дополнительного пожелания. До появления поля в интерфейсе
  существующий клиент может его не отправлять. Текст передаётся сценарию
  генерации вместе с городом и интересами, не подменяя их.

## Успешный ответ

Предлагается `200 OK`, `Content-Type: application/json`. Все показанные ключи
присутствуют, включая поля, для которых допускается `null`.

```json
{
  "city": "Иваново",
  "description": "Описание поездки",
  "image_url": null,
  "days": [
    {
      "date": "2026-12-01",
      "title": "Название дня",
      "summary": "Краткое описание дня",
      "image_url": null,
      "stops": [
        {
          "id": "source-id-1",
          "name": "Название места",
          "image_url": null,
          "latitude": 57.0,
          "longitude": 40.9
        }
      ],
      "route": null
    }
  ]
}
```

- `city` и `description` — строки для заголовка и описания поездки. `days` —
  массив дней в порядке дат. Его длина равна запрошенному `days`, дата первого
  элемента равна `start`, последующие даты идут подряд. Пример выше сокращён:
  фактический ответ на пример запроса должен содержать два дня.
- `title` и `summary` — строки для экрана дня и карточки дня. `stops` —
  упорядоченный массив основных мест дня; номер в списке и на карте равен
  индексу массива плюс один. `id` — строковый ID источника, `name` — название.
  Места, выбранные моделью, должны быть проверены по источникам.
- `latitude` и `longitude` — десятичные градусы WGS84; оба числа либо оба
  `null`, если координат нет. Координаты не выдумываются. Место без координат
  остаётся в списке; его номер не перенумеровывает остальные маркеры.
- `route`: объект маршрута дня либо `null`, если геометрии нет. Предлагаемый
  формат объекта: `{ "geometry": { "type": "LineString", "coordinates":
  [[долгота, широта], ...] } }` (GeoJSON, WGS84). Порядок точек на линии
  должен соответствовать порядку `stops`; существующий OSRM polyline нужно
  преобразовать на сервере. Геометрия не заменяет координаты мест.
- Тексты описания не должны содержать непроверенные факты. TODO: согласовать
  поведение, когда описания, места, координаты или геометрия недоступны;
  в частности, не считать условную схему реальной картой.

Поля `image_url` описаны ниже. ID поездки, сохранение, запасные точки, рейтинги,
время и стоимость здесь не требуются текущим интерфейсом и не являются частью
предлагаемого контракта.

## Изображения и запасной вариант

Каждое `image_url` — абсолютный HTTP(S) URL изображения или `null`; бинарные
файлы и локальные имена ресурсов интерфейса в JSON не передаются. URL должен
быть доступен браузеру. Сервер передаёт только известные изображения, без
выдумывания ссылок:

1. `stops[].image_url` — изображение конкретного места либо `null`.
2. `days[].image_url` — изображение одного из основных мест этого дня; если
   ни у одного места нет изображения, `null`.
3. `image_url` поездки — изображение одного из её дней; если ни у одного дня
   нет изображения, `null`.

Выбор среди нескольких подходящих изображений выполняет сервер; одинаковые URL
в ответе допустимы. Фронтенд должен обрабатывать как `null` и отсутствующее поле
(для совместимости), так и ошибку загрузки URL. Для недоступного изображения
он показывает локальную картинку по умолчанию соответствующего типа. Фолбэк
должен работать и для фоновых CSS-изображений, не только для `<img>`; ошибка
загрузки самой локальной заглушки не должна вызывать бесконечные повторы.
Нельзя подставлять заглушку места как реальную фотографию другого места.

## Ошибки и ожидание

Успешный HTTP-ответ содержит полную поездку; фронтенд ждёт его и показывает
состояние загрузки. Ошибка сети, невалидный ответ или неуспешный HTTP-статус
не должны отображаться как готовый маршрут. Валидацию JSON выполняет FastAPI;
сообщения показываются на русском без секретов и технических трассировок.

## Этап реализации

Контракт принят; подключён временный адаптер однодневного пайплайна.
Настоящая многодневная генерация и источник фотографий остаются отдельной задачей.

Фотографии-заглушки, предоставленные пользователем, сохранены в
`app/frontend/public/img/fallbacks/`: дети, еда, искусство, необычные места и
«красивые места». Они используются как локальные заглушки; если для интереса отдельной фотографии нет, используется «необычные места».

### Уточнение границ реализации

API передаёт параметры подключённому генератору и принимает от него готовую
поездку по схеме. API не реализует BM25 и не распределяет места по дням.
Временно используется адаптер, описанный ниже. Фотографии, приложенные
пользователем, предназначены для заглушек.

При локальном запуске Vite перенаправляет `/api` на `http://127.0.0.1:8000`.
Фронтенд отображает геометрию и координаты на интерактивной подложке OpenStreetMap.

Дата начала проверяется по локальной календарной дате процесса сервера; точный
часовой пояс развёртывания остаётся TODO.

### Подключение генератора

Переменная окружения `TRIP_GENERATOR_FACTORY` может содержать имя фабрики в
формате `python.module:factory`. Фабрика без аргументов возвращает объект с
асинхронным методом `generate(TripRequest)` и подключается один раз при запуске
сервера. Без этой настройки используется временный адаптер. Ошибочная
настройка прерывает запуск, чтобы не создавать впечатление работающего сервиса.

### Временное подключение существующего пайплайна

По явному разрешению пользователя до появления нового генератора API использует
существующий однодневный пайплайн, включая его векторный индекс. Это временное
исключение из запрета на готовые поисковые индексы, не реализация BM25. Для
запроса на несколько дней сценарий вызывается один раз; остальные дни — копии
первого с последовательными датами. Порядок мест берётся из `waypoints` OSRM.
Промпт и названия выбранных интересов передаются пайплайну как пользовательский
запрос. Источник фотографий в пайплайне отсутствует, поэтому `image_url` равен
`null`, а фронтенд показывает предоставленные заглушки. Геометрия OSRM polyline
преобразуется в GeoJSON. Факты о местах и изображения не выдумываются.

По умолчанию API подключает этот адаптер; `TRIP_GENERATOR_FACTORY` позволяет
заменить его совместимым многодневным генератором. При недоступных зависимостях
или отсутствующих местах API возвращает ошибку, а не демо-маршрут.

## Интерактивная карта дня

Карта дня использует Leaflet и подложку OpenStreetMap, как в предоставленном
пользователем примере. Пользователь может перемещать карту и менять масштаб
кнопками, колесом мыши или жестом. На карте отображаются пронумерованные места
в порядке списка; при выборе маркера показывается название места. Геометрия
GeoJSON отображается линией; если геометрии нет, но есть несколько точек,
они соединяются пунктиром. Карта автоматически показывает все доступные точки
и геометрию выбранного дня. Места без координат остаются в списке без маркера.
При отсутствии всех координат и геометрии выводится сообщение о недоступности
карты. Для загрузки картографической подложки нужен доступ в интернет.
